# Home Assistant Integration Repository Contract

This repository is the canonical source for its Home Assistant custom
integration. These rules are mandatory for every human or automated agent.

## Source-of-truth rules

- Make production changes in this repository, never only in a live
  `custom_components` directory.
- Treat a live-only difference as uncommitted source: preserve the diff, bring
  it back to a branch here, add tests, review it, and publish it through the
  normal release path.
- Do not finish with a manual overlay. The final live tree must come from the
  exact GitHub release recorded as installed by HACS.
- Keep credentials, tokens, account data, packet captures, databases, Home
  Assistant `.storage`, and rendered device URLs out of Git. Use documented
  private configuration paths and sanitized examples instead.

## Working-tree hygiene

- Work on a topic branch and use a pull request. Do not commit directly to the
  default branch.
- Never commit AppleDouble files, caches, generated bytecode, editor swap
  files, one-shot probes, `zz_*` migrations, backup copies, captures, or local
  `.env`/secret files.
- Put temporary diagnostics under an OS temporary directory. Put rollback
  snapshots outside the live integration directory.
- Preserve unrelated work. Stage explicit paths and verify `git status` before
  every commit.

## Change and release gate

Before merge:

1. Update or add behavioral tests for every production-code change.
2. Run the repository's complete lint, test, manifest, HACS, and secret-scan
   checks.
3. Confirm the manifest version is a valid release version and the release tag
   matches it with exactly one leading `v`.
4. Confirm the committed tree contains no live-only or temporary artifacts.

For a NAS deployment:

1. Merge the reviewed change and publish an installable GitHub tag/release.
2. Back up the current integration and HACS metadata outside
   `custom_components`.
3. Install that exact release through HACS; do not copy files over the HACS
   installation as the final step.
4. Verify HACS repository, installed version, and installed commit.
5. Compare the live integration tree byte-for-byte with the released tree,
   excluding only runtime caches such as `__pycache__` and `*.pyc`.
6. Verify Home Assistant health, startup logs, representative entities, and
   any device behavior changed by the release.

Do not declare completion while tests fail, the working tree is dirty, HACS
metadata disagrees with the live version, or the live tree differs from the
published release.
